# ECHORATE: мастер-контекст репозитория

Этот файл нужен агенту, который впервые открыл `videonew`. Он объясняет, что это за проект, где лежит источник правды и какой маршрут использовать перед изменениями.

## Что это

`videonew` содержит производственную систему TikTok-канала ЭХО `@echomgn` и лиги `@echorate`.

Главная идея канала: русский рэп подаётся через рейтинговые карточки в логике футбольных игр. У артиста есть позиция, статы, OVR и потенциал. Цифры служат аргументом для спора со зрителем.

Производственная цепочка:

```text
источники и JSON
-> рейтинговый движок
-> текст и структура деки
-> HTML/CSS
-> Chromium
-> PNG
-> автоматический QA
-> визуальный просмотр
-> описание
-> публикация
```

## Порядок чтения

Перед любой содержательной задачей прочитать:

1. `AGENT_CONTEXT.md`
2. `AGENTS.md`
3. `prompts/master-prompt.md`
4. профильный файл из таблицы ниже

`SKILL.md` содержит короткий рабочий маршрут. Он помогает войти в задачу, но не заменяет профильные спеки.

## Источники правды

Если два документа расходятся, ориентироваться на более узкий источник правды для конкретного вопроса.

| Вопрос | Источник правды |
|---|---|
| Формулы и коэффициенты | `rating/data/model.json`, затем `rating/core.py` |
| Данные артистов лиги | `rating/data/artists.json` |
| Кандидаты и резерв | `rating/data/candidates.json` |
| Сезоны | `rating/data/seasons_input.json`, `rating/season.py` |
| Прайм-карты | `rating/data/primes.json`, `rating/prime.py` |
| Анатомия карты | `formats/card-spec.md` |
| Форматы выпусков | `formats/formats.md`, `formats/data/registry.json` |
| Текст | `prompts/style-rules.md` |
| Дизайн | `prompts/design-rules.md` |
| Сборка и рендер | `build/README.md` |
| Описание | `ops/description.md` |
| Публикация | `ops/publishing.md` |
| Факты и источники | `ops/factcheck.md` |
| Исправления опубликованных данных | `ops/corrections.md` |
| Ошибки и лечение | `ops/mistakes.md` |
| Решения по контенту | `ops/analytics.md` |

`CHANGELOG.md` объясняет, почему правило изменилось. При конфликте старой документации с более свежей реализацией агент обязан исправить документацию в том же патче.

## Архитектура

### rating/

Математика проекта.

`rating/core.py` является общим ядром. Числа модели вынесены в `rating/data/model.json`.

Есть три разных типа рейтинговой карты:

| Тип | Движок | Данные | Статы |
|---|---|---|---|
| Лига на сегодня | `core.rate` | `artists.json` | 6 |
| Итог сезона | `core.season_score` | `seasons_input.json` | 5 |
| Прайм артиста | `prime.build` | `primes.json` | 5 |

Подмена одного движка другим ломает смысл карты.

### rating/data/

Данные отделены от кода. Артист лиги должен иметь обязательные источники `src_top5`, `src_live`, `src_scene`. Кандидат остаётся в `candidates.json`, пока обязательные поля для лиги не закрыты.

### build/

Генерация и рендер.

Кадры собираются HTML и CSS, затем Chromium снимает PNG. `build/qa.py` ловит измеримые проблемы. Контактка всё равно просматривается глазами, потому что автоматический QA не оценит кроп лица и визуальную иерархию.

### formats/

Спеки форматов. Слово `карта` всегда означает рейтинговую карточку по `formats/card-spec.md`. Слайд, таблица и карточка являются разными сущностями.

### prompts/

Правила текста, дизайна и логики деки. `prompts/master-prompt.md` задаёт общий контракт, профильные файлы уточняют его.

### ops/

Операционный слой: аналитика TikTok, фактчек, публикация, описание, журнал ошибок, коррекции и проверки репозитория.

### refs/

Эталонные кадры и проверки визуального канона.

### iceberg/

Схема и данные отдельного формата айсберга.

## Инварианты проекта

- Каждая цифра на кадре имеет источник.
- Судейская часть лигового OVR весит максимум половину.
- Опубликованный старый балл не переписывается тихо. Изменение показывается зрителю.
- Сезон, прайм и лига считаются разными движками.
- Источники остаются в данных и фактчеке, на карту они не печатаются.
- Данные и вёрстка разделены.
- Перед выдачей PNG просматриваются глазами.
- Описание проверяется `ops/desclint.py`.
- В описании используется 0 или 1 хештег. Серийный тег: `#эхо`.
- Рабочая длина карусели сейчас 6 или 7 кадров. Восьмой кадр требует причины.

## Как делать новый выпуск

1. Проверить героя и формат в `formats/formats.md`.
2. Собрать факты и записать источники.
3. Выбрать правильный движок.
4. Посчитать результат кодом.
5. Свериться с `ops/corrections.md`.
6. Написать текст по `prompts/style-rules.md`.
7. Собрать деку по `build/README.md`.
8. Прогнать линтер и QA.
9. Открыть контактку и проверить каждый кадр.
10. Собрать описание по `ops/description.md`.
11. Пройти публикационный чек-лист из `ops/publishing.md`.

## Как менять систему

При изменении формулы, схемы данных или публичного правила:

1. Изменить единый источник правды.
2. Добавить или обновить тест.
3. Обновить документацию, которая дублирует правило.
4. Добавить запись в `CHANGELOG.md`.
5. Запустить полную проверку.

Команды репозитория:

```bash
python3 ops/validate_data.py
python3 ops/selfcheck.py
cd rating && for t in test_*.py; do python "$t"; done
cd ../ops && for t in test_*.py; do python "$t"; done
cd .. && python3 refs/verify.py
```

Для конкретного выпуска дополнительно запускаются `build/lint.py`, `build/qa.py` и `ops/desclint.py`.

## Что считать текущей стратегией

Стратегические выводы живут в `ops/analytics.md` и `ops/publishing.md`, потому что они меняются быстрее архитектуры.

На снимке 7 августа 2026 лучше всего подтверждены следующие вещи:

- карусели на 6 или 7 кадров держат глубину лучше длинных;
- дуэль даёт сильный сигнал на репост;
- главный узкий участок воронки сейчас переход в профиль и подписка;
- фиксированный вечерний слот снят, идёт эксперимент со слотами около 10:00 и 16:00 МСК.

Эти пункты нельзя превращать в вечные правила. После нового снимка аналитики они пересматриваются.

## Перед PR

Минимум:

```bash
python3 ops/validate_data.py
python3 ops/selfcheck.py
```

Если менялась математика, обязательно запустить тесты `rating/`. Если менялась операционная проверка, запустить тесты `ops/`. Если менялся дизайн, проверить эталоны и открыть результат глазами.
