# Правки мастерпромпта под v4.0

Файл `prompts/master-prompt.md` содержит три утверждения, которые расходятся с кодом или с данными.
Править вручную, чтобы не затереть остальной текст.

## 1. Слот публикации опровергнут

Где: правило про окно 17:00 до 21:30 МСК.

Собственные данные говорят другое. Два лучших результата вышли в 15:49 и 10:30.
Оба вечерних выпуска оказались в нижней половине таблицы.

Заменить на ссылку: слот публикации определяется в `ops/publishing.md` и пересматривается по данным.

## 2. Возрастной бонус описан неверно

Где: раздел 2.4.

Сейчас бонус подан списком по именам артистов. В коде это таблица по возрасту плюс поправка на форму.

```
возраст до 21 включительно   +8
до 24                        +6
до 27                        +4
до 30                        +2
до 33                        +1
старше                       0
возраст неизвестен           +2

форма выше +10             +3
форма ниже -10             -2

ПОТЕНЦИАЛ = min(99, max(OVR, OVR + бонус за возраст + поправка на форму))
```

Цифры живут в `rating/data/model.json`, ключи `age_bonus` и `form_bonus`.
В промпте держать ссылку на файл, чтобы числа не расходились в третий раз.

## 3. Три формата в сутки не выполняются

Семь из восьми публикаций это фотокарусель. Правило существует только на бумаге.

Либо снять правило, либо свести к реальности: одна карусель в сутки плюс одно видео в неделю.

## 4. Добавить в промпт шаг проверки

Перед сборкой выпуска выполняется:

```bash
cd rating && python3 echorate.py --check && python3 test_rating.py
```

Если `--check` вернул ошибку, выпуск не собирается.
После рендера выполняется `python3 build/lint.py` и `python3 build/qa.py`.

## 5. Закрепить правило про пустую позицию

Формулировка для промпта:

> Пустая позиция лучше выдуманного числа. Если кандидатов на слот нет, слот остаётся пустым и на кадре об этом говорится прямо.

Это уже закреплено тестом `test_toty_no_position_swap` и докстрингом `formats.py`.

## Новые грабли для ops/mistakes.md

### Цифры из репозитория копируются чтением файла

При переносе пула 2017 в `seasons_input.json` часть цифр была восстановлена по памяти.
PHARAOH получил 89 вместо опубликованных 87. Тест `test_season_2017` упал:

```
AssertionError: [('PHARAOH', 89), ('ЛСП', 88), ('СКРИПТОНИТ', 85)]
пройдено 27 из 28
```

Лечение: перечитать исходный файл с GitHub и скопировать бит в бит.
Вывод: регрессионный тест поймал ошибку до эфира. Ради этого он и написан.

### Дублирование источника правды

Массив `ARTISTS` в `echorate.py` и файл `data/artists.json` хранили одни и те же поля и разошлись.
В v4.0 данные лежат только в JSON. Любое новое число в `.py` это повод откатить правку.

### Возраст константой тихо устаревает

Возраст был записан числом и ломал ПОТЕНЦИАЛ каждый год без единого предупреждения.
Теперь он считается от `born`. Артист без `born` ловится командой `--check`.
