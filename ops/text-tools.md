# Текстовый пайплайн

Главный фильтр текста живёт внутри репозитория и работает без внешних сервисов.
Внешние инструменты дают второй взгляд и остаются опциональными.

## Порядок

```text
черновик LLM
-> ops/slop.py
-> ops/neuroslop.py
-> точечная правка отмеченных мест
-> LanguageTool при наличии локального сервера
-> финальный текст
-> render
```

`ops/slop.py` отвечает за точные запрещённые фразы. Его совпадение блокирует
сборку.

`ops/neuroslop.py` считает редакционный `neuroslop_score` от 0 до 100. Он
смотрит на ритм, повтор тезиса, шаблонные контрасты, двоеточия и абстрактные
финалы. В CI потолок равен 65. Значение от 25 печатается как предупреждение.

Vale дублирует часть правил в редакторе. Конфиг лежит в `.vale.ini`, правила
в `styles/ECHO/`. Vale удобен до коммита, но CI от него не зависит.

LanguageTool нужен для русского: грамматика, опечатки, повторы. Обвязка
`ops/languagetool.py` работает с локальным HTTP-сервером. По умолчанию адрес
`http://127.0.0.1:8081`. Другой адрес задаётся переменной `LANGUAGETOOL_URL`.

## Команды

```bash
make slop
make neuroslop
make prose

vale prompts build/decks/*.desc.txt
python3 ops/languagetool.py build/decks
```

`make prose` не требует запущенного LanguageTool. Если сервера нет, слой
грамматики печатает пропуск и завершает работу без ошибки.

Для обязательной проверки конкретного текста:

```bash
python3 ops/languagetool.py build/decks/имя.desc.txt --required
```

## Что переписывает агент

Агент меняет только фрагменты, которые отметил линтер. Чистые предложения
остаются на месте. После правки весь файл прогоняется снова.

Автоматический `--fix` для текста проекта не используется. Формально верная
замена может сломать голос автора или смысл цифры.

## Контрольный тест

```bash
python3 ops/neuroslop.py --self-test
```

Внутри два коротких примера. Шаблонный должен получать высокий скор,
конкретный человеческий текст низкий. Это регрессия самого скорера.

## Внешние проекты

- Vale: `vale-cli/vale`, ветка v3, MIT.
- LanguageTool: `languagetool-org/languagetool`.
- Идеи готовых англоязычных правил можно брать из proselint и write-good,
  затем переписывать под русский и правила ECHORATE.

Сторонний код внутрь проекта не копируется. В репозитории лежат свои правила
и тонкая обвязка вокруг локальных инструментов.
