# Визуальная система ECHORATE

Этот файл дополняет `prompts/design-rules.md`. Базовая геометрия кадра,
палитра и шрифты остаются там. Здесь правила для графиков, схем и сложных
сравнений.

Подход собран после разбора `cathrynlavery/diagram-design`. Репозиторий дал
полезные принципы: единые токены, сетка, бюджет сложности, один фокус и
отдельная грамматика для каждого вида визуализации. Код донора внутрь
ECHORATE не копируется.

## Главный тест

Перед схемой задаётся вопрос: зритель поймёт мысль быстрее, чем из двух строк
текста или простой таблицы?

Если ответ отрицательный, схема не нужна.

## Один кадр, один фокус

На кадре максимум два визуально громких элемента. Обычно главный элемент один.

Фокусом считается:

- крупная цифра;
- карточка артиста;
- выделенная серия графика;
- победитель сравнения;
- фото, если оно занимает больше половины тела кадра;
- крупная рукописная пометка.

Цвет не используется как украшение. Красный, зелёный и золото работают только
как смысловой сигнал. Общий потолок цвета остаётся 5 процентов площади кадра.

## Сетка

Новые SVG и графические примитивы строятся на сетке 4 px.

Координаты, размеры узлов, внутренние отступы и интервалы кратны четырём.
Исключения: толщины линий, проценты и существующие границы кадра из
`build/qa.py`.

Рабочие интервалы:

```text
8  12  16  20  24  32  40  48  64
```

Новый компонент не вводит случайный отступ 27, 35 или 43 px.

## Бюджет сложности

Обычный кадр:

| Элемент | Потолок |
| --- | ---: |
| Фокусные элементы | 2 |
| Независимые визуальные группы | 4 |
| Цветные смысловые акценты | 2 |
| Серии графика | 4 |
| Подписи данных | 7 |
| Рукописные пометки | по общему бюджету деки |

Для конкретных типов:

| Тип | Потолок |
| --- | ---: |
| Radar | 6 осей, 2 серии |
| Line | 4 серии, 8 точек на серию с подписями только крайних значений |
| Bar | 8 столбцов |
| Timeline | 8 событий |
| Quadrant | 10 объектов |
| Table | 8 строк без режима dense |
| Stats | 6 осей рейтинга |

Если мысль требует больше, материал делится на обзор и деталь.

## Radar

Radar разрешён только для сравнения профиля двух артистов или двух сезонов.
Шесть осей ECHORATE сохраняются целиком:

ТЕКСТЫ, ЗВУК, ПОДАЧА, ХИТЫ, ЛАЙВЫ, ВЛИЯНИЕ.

Условия:

- максимум две серии;
- одинаковая шкала 30-99;
- подписи осей снаружи;
- заливка слабая, контур важнее;
- итоговый OVR рядом с radar не ставится, если он уже есть на соседнем кадре.

Radar не заменяет объяснение причин баллов. Он показывает форму профиля.

## Line

Line используется для динамики во времени: OVR по годам, прослушивания,
позиция в чарте, накопление голосов.

Правила:

- ось времени идёт слева направо;
- ноль используется там, где метрика имеет естественный ноль;
- шкала рейтинга может начинаться с 30, поскольку сама модель ограничена 30-99;
- подписи ставятся на начало, перелом и конец;
- случайные маркеры на каждой точке запрещены.

## Bar

Bar нужен для прямого сравнения категорий. Сортировка должна помогать чтению:
по значению, по времени или по заранее объявленному порядку осей.

Один акцентный столбец допустим. Остальные остаются чёрными или серыми.

## Timeline

Timeline показывает переходы и события, которые меняют состояние героя.
Событие получает короткую дату и одну строку смысла.

Если в событии нет изменения, оно удаляется.

Для эволюции артиста выбираются только годы с реальным сдвигом рейтинга,
звучания, масштаба или статуса. Полный календарь по одному событию на год
используется только в формате МАШИНА ВРЕМЕНИ.

## Quadrant

Quadrant подходит для двух независимых осей. Примеры:

- популярность / экспериментальность;
- текущий OVR / потенциал;
- охват формата / конверсия в подписку.

Оси подписываются словами и числами. Деление пространства объясняется в
заголовке, легенда внутри поля не ставится.

## Соединительные линии

Линия существует только там, где она передаёт связь или направление.

Для схем:

- прямые связи идут горизонтально или вертикально;
- сложный маршрут использует прямой угол;
- линии не проходят через чужой блок;
- несколько связей получают отдельные точки входа;
- подпись связи стоит рядом с линией и не перекрывает её.

Диагонали применяются только внутри графиков данных.

## Антипаттерны

Запрещены:

- тени;
- градиенты;
- стеклянные карточки;
- неоновое свечение;
- одинаковые скруглённые коробки для всего;
- цвет на каждом элементе;
- легенда поверх данных;
- декоративные иконки без смысловой функции;
- мелкие подписи, которые требуют зума;
- график ради заполнения пустого места.

## Встраивание в текущий стиль

Источник палитры один: `build/theme.css`.

Новые компоненты используют существующие роли:

```text
paper   var(--pap)
ink     var(--ink)
muted   var(--g)
rule    var(--ln)
growth  var(--grn)
fall    var(--red)
gold    var(--gold)
```

Новый локальный hex в компоненте требует причины. Если цвет уже есть в теме,
берётся переменная.

## Перед выдачей

1. Схема быстрее текста.
2. На кадре одна основная мысль.
3. Фокусных элементов максимум два.
4. Подписи читаются с телефона.
5. Цвет передаёт смысл.
6. Плотность укладывается в бюджет типа.
7. Соседний кадр визуально устроен иначе.
8. PNG открыт глазами после рендера.
